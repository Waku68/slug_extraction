## 共通のやり方：トークンを節約して、質は落とさない

トークンがかかるのは **画像を見る**、**大きなファイルを読む**、**長いログ**、**やり直し** の4つ。質を決めるのは **本物の手本**、**ナメクジの目の高さ**、**既知の失敗を踏まない** の3つ。だから次の順でやる。

### 1. 先に数字の表を1枚作る（やり直しを減らす）
- 造形ファイルの「決める数字」の表を、spec.md と `docs/tech/island_test_notes.md` の数字で埋めてから書く。わくさんに見せるのはこの表と、必要なら平面か断面の図1枚
- 数字は造形ファイルの冒頭の `const` にまとめる（わくさんが直すのも、次に読むのもそこだけ）

### 2. 新しく書かずに、使い回す
- 形はほとんど次の4つの型で作れる。新しい形も、まずどの型かを決める

| 型 | 中身 | 使っている所 |
| --- | --- | --- |
| 高さの式 | 地点 → 高さ。`Smooth`・`Smax`・`Fbm`・`Ridged`・`Sd`（多角形からの距離）・`Line`（線からの距離） | 山、台地、溶岩の流れ、海岸 |
| 断面 × 道筋（スイープ） | 道筋に沿って、同じ断面を並べる | 川（`Rivers`）、洞窟の通路（`TubeMesh`）、道（`Carve`） |
| 角度ごとの断面 | 中心のまわりに、角度ごとの断面を並べて1枚にする | 滝つぼの岩壁（`BuildFalls`） |
| 緯度と経度 | 球を切ってでこぼこにする | 洞窟の部屋（`DomeMesh`）、岩（`RockMesh`） |

- 部品：`Mat`（マテリアル）、`CaveMat`（両面）、`SaveMesh`、`MeshObject`（当たり判定つき）、`Rock`、`Soft`、`Tree`、`Log`、`Resample`、`Chaikin`、`HmAt`、`W`（地図の座標から世界へ）
- **地形でできる所は地形で**。モデルは、地形でできない所（垂直より急、張り出し、天井、落ちる水）だけ

### 3. 数字で確かめて、絵は最後に見る
- 作ったら、まずログ1行で確かめる：いちばん急な角度、這う時間（`Measure Flow`、`Measure Ways`、`Measure Coast Round`）、高さ（`Heights`）、穴の数
- 造形ファイルの「確かめる（数字）」の項目をログに出す。数字がおかしければ、絵を撮らずに直す
- ログは要約1行。点ごとに出さない

### 4. 撮る枚数を決めておく
- 造形ごとに決まった撮り方（造形ファイルの「撮る」）だけ。Shoot のメニューにしておき、作り直しのあと1回押す
- 確認用は小さく（600×300）。見せる用だけ 1200×600。同じ造形の絵は、できれば1枚に並べて見る
- 空からの1枚で形全体、ナメクジの目（0.47 m）で中・近の2枚。これ以上撮るのは、直す所が分かっていないとき

### 5. 読む量を小さく（1ファイル 500 行まで）
- 造形1つか場所1つにファイル1つ（今の partial class の分け方）。冒頭に「何を作るか、数字、考え方、焼いたか」のコメント。Claude はまず冒頭と、直す関数だけ読む
- **1ファイル 500 行まで**。超えたら、関数のまとまりで分ける（例：`IslandTest800Caves.cs` → 通路 `Caves.Tubes`、部屋 `Caves.Domes`、口と天窓 `Caves.Openings`）。分けたファイルの名前は `IslandTest800<造形>.<まとまり>.cs`。共通の部品は `IslandTest800Tools.cs` へ
- 500 行を超えたファイルは、次にそのファイルを触るときに分ける。分けるだけの作業はしない。分けたあとはコンパイルし、Build Scene をして、`Measure` の数字が分ける前と同じか確かめる（形が変わっていないこと）
- 前の会話の結果は `docs/tech/island_test_notes.md` の該当の節を読む（コードを全部読み直さない）

### 6. 灰色でシルエットを先に、細部はあと
- 灰色で形と遊び（這う時間、見通し、隠れる所）を決める。細部（地層の色、苔、水の動き）は、形が決まってから
- 細部は形を増やさずに出す：色の縞、モデルの岩を散らす、崖のすそに落ちた岩。三角形を増やすのは近くで見る所だけ

### 7. Blender は名所の大物だけ
- Blender の `look` は画像なので高い。地形・洞窟・道は Unity のコードで作る。Blender は大ガジュマルや目印の岩のような、1つだけの大物

### 8. 決まった所は焼いて固める
わくさんの ✅ が出た造形は、出来上がりをアセットに保存して、それからはコードで作り直さない。作り直しの時間も、Claude が読む量も、決まった所の数だけ減る。

- **焼く物**：
  - モデル（洞窟、滝の岩壁、橋、崩れた岩など）：メッシュを `.asset` に、置いた物をプレハブにする
  - 地形の高さ：大地の形（山・谷・海岸）が決まったら、TerrainData を焼いた版を正にする。それより後に足す形（道を掘る、洞窟の穴）は、焼いた高さの上にかける
- **置き場所**：`Assets/World/Baked/<島の名前>/<造形>/`（例 `Baked/Island800/Caves/`）。焼いた日と、どのコードで作ったかをフォルダの `README.txt` に1行
- **ビルダー**：造形ごとに `const bool <造形>Baked` を持つ。`true` なら焼いたアセットを置くだけで、作る関数は呼ばない。焼くメニューは `Slug/IslandTest 800 m/Bake/<造形>`
- **コード**：消さない。冒頭のコメントに「Oct XX 焼いた。`Baked/...`」と書く。焼いた造形のコードは読まない
- **もう一度直すとき**：`<造形>Baked = false` → コードを直す → 作り直して ✅ → 焼き直す。焼いた物を手で直さない（直すなら、そのことをコードの冒頭と `README.txt` に書く）
- 焼くのは ✅ の後だけ。まだ形を探している造形は焼かない

## 品質の線（どの造形でも守る）
- 造形ファイルの「本物の手本」を1行で決めてから作る。その手本の「どこが本物らしいか」を形の操作に直す
- ナメクジの目の高さ（0.47 m）で見て、何に見えるか1語で言える
- 這える：50° まで登れる。段差は 0.45 m まで。道は 15°（どうしてもなら 22°・30°）
- 造形ファイルの「失敗しやすい」を、撮る前にひと通り確かめる

## 安くする道具（`IslandTest800Tools.cs`、メニュー `Slug/IslandTest 800 m/...`）
| メニュー | すること | 使いどころ |
| --- | --- | --- |
| `Rebuild Caves Only` | 地形はそのままで、洞窟のモデルと地形の穴だけ作り直す（約 4.5 秒。Build Scene は約 20 秒） | 通路・部屋・口の形を直すとき。地形の高さを変える形（入江、くぼみ）は Build Scene |
| `Check Cave Gaps` | 洞窟の中から光線を飛ばして、空が見える所を数え、多い順に場所を出す（地形の裏が見える所／口でも天窓でもない穴）。約 1 秒 | 洞窟を作り直すたび、撮る前に。0 になってから撮る |
| `Sheet/<名前>` | Shoot のメニューの絵を、小さく番号つきで1枚に並べる（`Screenshots/Island800/sheet_<名前>.png`） | 確認用。見せる用の大きい絵は今までの Shoot |

- どれも、スクリプトを直して Unity が読み直したあとでも動く（ビルドの中身を作り直してから動く）
- Claude は `execute_code` で `SlugExtract.IslandTest800Builder.CheckCaveGaps()` などを呼ぶと、結果の文字が返る（ログを読みに行かなくていい）

`ShotUtil.BeginSheet` ～ `EndSheet` の間は、どの `ShotUtil.Capture` も1枚の絵に並ぶ。ほかのシーンの Shoot にも使える。
