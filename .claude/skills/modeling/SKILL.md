# モデリングの進め方

わくさんの指示は、下の **共通の型** ＋ カテゴリごとの **追加の欄** で受け取る。型が埋まっていなくても止まらない：空欄は Claude が決めて、作り始める前に「こう決めた」を一覧で見せる。聞き返すのは「ひとこと」と「大きさ」が両方ないときだけ。

| カテゴリ | 読むファイル | 主に作る場所 |
| --- | --- | --- |
| マップ（地形、区画、名所、巨大な木や岩） | [map.md](map.md)。形は造形ごとに [shapes/](shapes/README.md)（崖、谷、川、滝、海岸・入江、洞窟、天窓、道、隠れる物） | 地形と配置は Unity のコード（シーンのビルダー）、名所の大物だけ Blender |
| ナメクジ（体、装備、バッグ、銃・道具） | [slug.md](slug.md) | Unity のコード（`SlugMeshFactory`、`GearMesh`、`ProfileMesh`）。Blender は使わないのが基本 |
| 植物 | [plant.md](plant.md) | Blender のスクリプト（`Blender/Harvest/<name>_gen.py`） |
| 鉱石・塩 | [ore.md](ore.md) | Blender のスクリプト（`Blender/Harvest/<name>_gen.py`） |

モデリングの決まりは `docs/modeling/README.md`（Claude と Argon 共通）。ツールの癖は memory の Blender MCP・Unity MCP のメモを見る（Blender 5.2 の bpy の落とし穴、再生を止めてからスクリプトを直す、など）。

## 共通の型（わくさんが書く）

```
【作る物】 名前 ／ カテゴリ（マップ・ナメクジ・植物・鉱石）
【ひとこと】 どんな物か1行（例：雨上がりにだけ生える、ころんとした青いキノコ）
【形のことば】 3つまで（下の表から。なければ自由に）
【大きさ】 ナメクジと比べて（ナメクジ＝体長 1.1 m、目の高さ 0.47 m）
【どこから見る】 這う目の高さ ／ 手に持って一人称 ／ 遠くから ／ 左上の小さな自分
【変わる】 段階や状態（採る前→掘りかけ→切り株、乾季は赤、しおれる…）
【色】 部品ごとに。全部で2〜4色
【参考】 写真・実物・ゲーム。どこが良いのかを一言
【やめて】 こうはしないで
【何案】 1案で詰める ／ 3案並べて選ぶ（決めてなければ3案）
＋ カテゴリごとの追加の欄
```

一番効くのは **【ひとこと】【大きさ】【どこから見る】** の3つ。形の細かさより「どの距離で、何と比べて、何に見えればいいか」が決まっていると外れにくい。

## 形のことば（わくさんの言葉 → Claude がやること）

| ことば | 形の操作 |
| --- | --- |
| ころん | 球に近い。高さ≒幅、下を少しつぶして座りを良く |
| ずんぐり | 太さ／長さを大きく（0.5 以上）。先を細くしない |
| ひょろ長い | 太さ／長さ 0.15 以下。少し曲げる |
| とがった | 先が点に収束。円錐、角を立てる |
| ぽってり | ふくらみの一番太い所を下寄りに。縁に厚み |
| 平たい | 高さを幅の 1/3 以下に |
| ごつごつ | 大きめの凹凸（大きさの 10〜20%）、面はカクカク |
| すべすべ | 凹凸なし、分割を増やす |
| かくかく／結晶っぽい | 平らな面と立った角。立方体・柱を組む |
| くたっと | 先が重さで垂れる。曲げを根元より先に |
| 群れ | 同じ部品を大きさ・向きを少しずつ変えて 3〜7 個 |
| 古い・使い込んだ | 角を丸く削る、欠け、色の端を暗く |

ポップの決まり：細部を足すより **シルエットを大げさに**。部品は少なく、1つずつ大きく。

## 直しの言い方（わくさんが返すとき）

「**どこ** を **どう** **どれくらい**」の3つで言ってもらうと1回で直る。

- 例：「かさを 平たく 半分くらい」「葉を 2 枚減らす」「全体 もっとナメクジ寄りの大きさに（今の 7 割）」
- 「なんか違う」のときは、Claude が違いそうな所を3つ挙げて、それぞれ極端に振った版を並べる

## Claude の進め方

1. **読む**：カテゴリのファイル、spec.md の該当の章、同じカテゴリの既存のスクリプト（同じ作りに合わせる）
2. **食い違いそうな所を先に聞く**：わくさんの絵や言葉の読み方が分かれそうな所（絵の向き、天井の有無、大きさ、場所、何をする所か）は、作る前に質問で確かめる（おすすめを1つ目に、2〜4問）。技術だけの選択は Claude が決めて進める
3. **決めたことを見せる**：型の空欄を埋めた一覧を短く出す（作り始める前）
4. **ラフ（形だけ）**：色なし・灰色の塊で、案の数だけ並べる。必ず横に **比べるナメクジ**（体長 1.1 m・高さ 0.5 m のカプセル。Unity なら `Slug_Pop` プレハブ）を置く
5. **撮って見せる**：【どこから見る】の距離・高さから撮る。Blender は `look`（max_size 小さめ）、Unity はゲームのカメラ。案を1枚に並べて番号を付ける
6. **選んだ案を詰める**：色、段階、細部。もう一度撮る
7. **ゲームに入れる**：書き出し → Unity でマテリアルをつなぐ → 実際のシーン（ExtractTest など）で、這う目の高さから撮る。ここで初めて「完成」と言える
8. **記録する**：スクリプト冒頭のコメント（何を作るか、形の考え方、色）、`docs/README.md` の Assets の地図、必要なら spec.md・progress.md

ラフで1往復するのが一番安い。色や細部を作り込んでから形がちがうと分かるのを避ける。
