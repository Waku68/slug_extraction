## 1. どんなゲーム？

**雨の夜、塩を撃ち合うナメクジたちの一人称PvP脱出ゲーム。** 見た目はシック×ポップ、失う痛みはハード。

人類が滅んだあとの熱帯の島。ナメクジたちは人の技術を受け継いで、自分たちの文明で暮らしている。島は年々乾いていき、湿った土地と資源が減るので、奪い合いになる。

**1回の遊び（出撃）の流れ**

1. 拠点（石灰岩の崖の洞窟の工房）で、持ち物を選ぶ（ピッケル・銃・バッグ）
2. 大きなペリカンに籠で運ばれて、島へ
3. 島で塩や植物を採って、背中の布のバッグに詰める。重いほど遅くなる
4. ほかのプレイヤーに見つかれば、塩の弾で撃ち合い。倒れたら、持っていた物は全部その場に落ちる
5. 生きてベースキャンプに戻れたら、持ち帰った物が自分の物。お金（アモレ）に換えたり、拠点を育てたりする

**ゲームの柱**（迷ったらここに戻る）

1. 物を手に入れた高揚感、バッグが埋まっていく充足感、持ったまま帰る緊張感
2. 雨に濡れた自然を、歩いて、採って、持ち帰る手ざわり
3. 自分らしさ

**ナメクジならでは**

- 乾くと弱る。日なた・塩の上で乾き、雨・日陰・水たまりで潤う。乾ききると倒れる。ゲージはなく、体の見た目と触角と音で分かる
- 体力ゲージもない。撃たれると体に白い塩の跡が残り、それが体力
- 島の時計は現実の時刻と連動していて、1日 9.5 時間。季節・月・潮・天気がある。みんな同じ空の下
- 一番喜ばせたい人は「友達と2〜4人で、重い荷物を持って帰るのが好きな人」

**島**：800 m 四方。真ん中に岩塩の山（113 m、一番稼げて一番危ない）、東に雨の森、西に砂漠と赤い台地と枯れた谷、北に黒い溶岩原、南に花の草原。川が2本、滝、塩田。地図は `docs/island_map.svg`。

**いまどこまでできているか**（Nov 5）

- 1人で島を歩いて、採って、乾きと天気の中を持ち帰れる。体は2本足（Nov 2 に這う体から変えた）
- 岩塩の山にボット（最大3体）がいて、撃ち合える
- 拠点は「灰色の箱」（形だけ）。仕上げはこれから
- **ほかのプレイヤーとはまだ会えない**（ネットワークはまだ）。いまの目標は「奪い合いは面白いか」を確かめること。ボット1体 → 2人 → 友達数人の順

もっと知りたいときは `docs/spec.md`（決まりの全部、長い）と `docs/progress.md`（進み具合と次にやること）。

## 2. わくの作り方（ここがいちばん大事）

わくは「監督」。手を動かすのは AI たちと仲間で、わくは見て、触って、決める。合わせてほしいことは次のとおり。

### 大事にしていること

| こと | どういうこと |
| --- | --- |
| **手ざわり** | 持つ・振る・跳ぶ・覗く。まず自分で遊んで、気持ちいいか。腕の浮きや手を添える位置まで見る |
| **遅いのは罪** | 待たされる、もっさり、面倒な手間は削る。移動の速さは決まっているので「遅くしよう」は言わない |
| **世界の筋** | 「この世界ならなぜそうなる？」。人間の物をそのまま持ち込むと気持ち悪い。理由があれば変な案ほど面白い |
| **体で分かる** | 数字やゲージは少なく、見た目・音・体の反応で伝える。でも情報が足りないのは嫌。お金だけは数字 |
| **満ちていく感じ** | 袋が埋まる、重い物を持ち帰る、大物を自慢する |
| **仲間と節目** | いっしょに出て、いっしょに帰って、机に中身をぶちまける |
| **雄大さと居心地** | 外は大きく見晴らしよく、帰る場所は硬派で落ち着く |

### 好きな形と見た目

- **ずんぐり、デフォルメ、部品は少なく特徴は濃く。** ポップだけど派手すぎない。彩度はひかえめ
- 苦手：つるつる、細くて写実的、のっぺり、どこかで見た既製品の感じ
- **テクスチャ（画像を貼る）は使わない。** 質は形・面取り・密度・光で出す
- 空気感の目標はゲーム「Cairn」：遠くほど霞む、影に色がある、植物は光の当たる大きなかたまり
- **かじれるかで面を分ける**：かじれない硬い物（岩・殻・乾いた木）はカクカクの面、かじれる物（葉・苔・縄）はなめらか
- 大きさはナメクジの目で考える。**ナメクジの目の高さは 0.47 m で、人の約 1/3.6。** 例：高さ 1 m の岩は、人にとって 3.6 m の岩

### 決め方

- **作る前に質問する。** 一番怖いのは読み違い（絵の向き、屋根の有無、大きさ、場所、何をする所か）。2〜4問、おすすめを1つ目に
- 形や遊び方が大きく変わるときは、**「無難」（いまの形を活かす）と「攻め」（いちばん遠くへ行く）の2案**を出す。わくは両方見て選ぶ
- 何案か並べて見せると、わくは「これ」と指さして決める。言葉より絵
- 作ったら、**決めたことの一覧と、ナメクジの目の高さから撮った絵**を見せる
- 決めたことも、遊んで違和感があればすぐ戻す。作った物を捨てるのはふつうのこと
- わくの「違和感ある」「微妙」は、怒っているのではなく、次の手がかり

### チーム

| だれ | 何をする |
| --- | --- |
| わく | 監督。音・地図・見た目の方向。調整の数字（`Assets/Tuning/`）、コミットと push、ファイルを消すこと |
| Claude（Claude Code） | コード、島の自然の形（Unity のコードで作る）、資料（`docs/`） |
| Argon（Google Antigravity の AI） | モデリング、効果音、島に植物を置く、拠点の仕上げ |
| きみ | 遊んで感想、島や場所づくり、Claude と作る |

Claude と Argon は `docs/worklog.md`（やりとり帳）で伝言し合っている。きみも同じ帳面を使う（5章）。

## 3. 1日目：道具をそろえる（Windows）

上から順に。全部で 1〜2 時間（ダウンロードしだい）。

### ① GitHub のアカウント

1. https://github.com で無料のアカウントを作る
2. **ユーザー名をわくに送る** → わくがリポジトリ（`Waku68/slug_extraction`、非公開）に招待する
3. 届いたメール（または GitHub の通知）で招待を受ける

> **GitHub とは**：プロジェクトの全ファイルと、その変更の歴史を置いておくネットの倉庫。わくの PC ときみの PC で、同じプロジェクトを持てる。

### ② Git と GitHub Desktop

1. **Git for Windows**（https://git-scm.com）を入れる。設定は全部そのままで OK（Git LFS もいっしょに入る）
2. **GitHub Desktop**（https://desktop.github.com）を入れて、①のアカウントでサインイン
3. GitHub Desktop で **File → Clone repository** → `Waku68/slug_extraction` を選ぶ。置き場所は **`C:\UnityProjects\ExtractionGame`** がおすすめ（わくと同じ。パスに日本語や空白を入れない）
4. 大きいファイル（音・モデル）も自動で落ちてくる。数 GB あるので待つ

> **Git を先に入れる理由**：このプロジェクトは Unity の部品（MCP for Unity）を Git で取ってくるので、Git がないと Unity で開いたときにエラーが出る。

### ③ Unity

1. **Unity Hub**（https://unity.com/download）を入れて、Unity のアカウント（無料の Personal）でサインイン
2. Hub の **Installs → Install Editor** で **6000.5.4f1** を入れる。一覧になければ https://unity.com/releases/editor/archive から同じ番号を探して「Unity Hub で入れる」。**番号は必ず同じに**（違うとファイルが勝手に書き換わって、わくとぶつかる）
3. 追加の部品（モジュール）は要らない
4. Hub の **Projects → Add → Add project from disk** で `C:\UnityProjects\ExtractionGame` を選んで開く
5. **初めて開くと 10〜30 分かかる**（`Library` という作業用の箱を作り直すため）。止めずに待つ

### ④ Claude

1. https://claude.ai でアカウントを作り、**Pro 以上のプラン**にする（Claude Code は有料プランが要る）
2. **Claude のデスクトップアプリ**（Windows 版）を入れて、サインイン
3. アプリの **Code** タブを開き、フォルダに `C:\UnityProjects\ExtractionGame` を選ぶ

### ⑤ Claude と Unity をつなぐ（MCP）

これで Claude が Unity を直接動かせる（物を置く、シーンを開く、エラーを読む、絵を撮る）。

1. Unity のメニュー **Window → MCP for Unity** を開く
2. 足りない物（Python や uv）があればウィンドウが教えてくれるので、案内どおり入れる
3. つなぐ相手に **Claude Code** を選んで設定する
4. Claude に「Unity とつながってる？」と聞いて、つながっていれば OK

うまくいかなければ、Claude にこの章とエラーの文を見せて「直して」と頼む。

## 5. GitHub の使い方（GitHub Desktop で）

### 言葉

| 言葉 | 意味 |
| --- | --- |
| **リポジトリ** | プロジェクトの倉庫（`Waku68/slug_extraction`） |
| **コミット** | 「ここまでの変更」に名前を付けて記録する。セーブポイント |
| **プッシュ（push）** | 自分のコミットを GitHub へ送る |
| **プル（pull）** | GitHub の新しいコミットを自分の PC へ持ってくる |
| **ブランチ** | 自分用の作業の線。わくの本線（`master`）を汚さずに作れる |
| **プルリクエスト（PR）** | 「このブランチを本線に入れて」というお願い。わくが見て入れる |
| **コンフリクト** | 2人が同じファイルの同じ所を変えて、ぶつかった状態 |

### 毎回の流れ

1. **始める前に Pull**（GitHub Desktop の「Fetch origin」→「Pull origin」）。わくの新しい変更をもらう
2. **自分のブランチを作る**：上の「Current branch」→「New branch」。名前は `自分の名前/やること`（例 `taro/forest-path`）
3. Unity で作業して、保存
4. GitHub Desktop の左に変わったファイルが並ぶ。**入れたい物だけチェック**して、下に何をしたか日本語で1行書いて **Commit**
5. **Push origin** で送る
6. **Create Pull Request** で PR を作り、わくに「見て」と言う。本線に入れるのはわく

### ぶつからないための決まり

- **シーン（`.unity`）は2人で同時に触らない。** シーンはぶつかると手で直せない。触る前に、`docs/worklog.md` の「いま作業中」に1行書く＋わくに一声かける。終わったら消す
- ファイルと同じ名前の **`.meta`** は必ずいっしょにコミット（Unity がつながりを覚えているファイル）
- 自分が触っていないのに変わったファイル（`Assets/Tuning/`、関係ないシーン、`ProjectSettings/` など）は、右クリック → **Discard changes** で捨てる
- 小さく、こまめにコミット。1つのコミットに1つのこと
- 困ったら、何も押さずに Claude かわくに聞く。消したり上書きしたりする前に聞く

### やりとり帳（`docs/worklog.md`）

Claude・Argon・わくが使っている伝言のノート。きみも使う。

- 作業の前に、**頭の 60 行だけ**読む（「いま作業中」と「伝言」）
- 相手に関係あるときだけ書く（同じファイルを触りそう、決まった数字を変えた、頼みたいことがある）。短く、3行まで

## 6. Claude Code の使い方

### Claude とは

Code タブの Claude は、このフォルダのファイルを読んで、書いて、Unity を動かせる。日本語で、ふつうに話しかければいい。

### 最初のひとこと（毎回の会話の始めに）

> `docs/friend_guide.md` と `AGENTS.md` と `docs/worklog.md` の頭を読んでから手伝って。

わくの Claude は、わくの好みを覚えている（メモリー）。**きみの Claude は覚えていない**ので、この手引きを読ませて合わせる。下の「Claude に守らせること」もこの手引きにあるので、読ませれば伝わる。

### 上手な頼み方

- **やりたいことを、ナメクジの目で言う**：「森の川を渡れる倒木の橋。ナメクジがちょうど歩ける幅で、人で言えば丸太の一本橋くらい」
- 絵があれば貼る（スクショ、手描き、参考写真）。言葉より伝わる
- 「作る前に質問して」と言うと、読み違いが減る
- 「3案見せて」と言うと選べる
- 作ったら「ナメクジの目の高さから絵を撮って」と頼む
- **1つの作業が終わったら、新しい会話にする。** 同じ会話を続けると、だんだん遅く高くなる。終わる前に「決まったことをファイルに書いて」と頼む
- Claude が「〜していい？」と聞いてきたら、分からなければ「どういうこと？」と聞き返す

### Claude に守らせること（わくの決まり）

- 再生中にスクリプトを直さない。止めてから直す
- 島の **岩塩の山はわくが手で作っている**。コードで作り直さない
- テクスチャは使わない
- 登れるかは、坂の角度ではなく、ナメクジの大きさで実際に歩かせて確かめる
- 消すのはわく。git のコミット・push は、きみが頼んだときだけ
- 作ったら、見られるシーンに置く（植物なら `IslandPropsLook`）

## 7. 頼まれていること、それぞれの始め方

### A. 遊んで感想

1. `IslandTest_800` や `ExtractTest` で遊ぶ
2. 感じたことを**そのまま**言う。うまく言えなくていい。わくがいちばん欲しいのは「違和感」
   - いい例：「塩を掘ってバッグに入れるまで押す回数が多くてだるい」「撃たれたのに気づかなかった」「この坂、登れると思ったら登れなかった」
   - **どこで**（スクショか、だいたいの場所）と、**何をしていたか**を添える
   - Windows は **Win+Shift+S** でスクショ、**Win+G** で動画
3. 前に友達が遊んだときの感想は、本当に仕様を変えた（`docs/discussions/friend_playtest_discussion.md`）。遠慮しない

### B. 島や場所づくり

場所は `Assets/Scenes/Game/IslandTest_800.unity`。

- **触らない物**：岩塩の山（わくが手で作っている）、Argon が置いている `Map/植物（Argon）`・`Map/岩と倒木（Argon）`
- **道や橋の作り方**（`Map/通路`）：Hierarchy の `Map/通路` の中に、点（小さな箱）が順に並んでいる。点を動かすか足して、メニュー **Slug → IslandTest 800 m → Walkways → Rebuild** を押すと、点を通る板の道・橋・はしごができる。**Walkways → Walk Test** でナメクジの大きさで歩けるか確かめる
- **Slug → IslandTest 800 m → Walk Map** で、歩いて行けない所が分かる
- 物を置くときは、ナメクジの目の高さ（0.47 m）で見て確かめる。Scene の視点を地面すれすれに下げるとそれっぽく見える
- 何を作るかは、先にわくと話す。作ったら、ナメクジの目の高さの絵を見せる

### C. Claude と作る

1. わくに「次なにやる？」と聞くか、`docs/progress.md` の 3章（決まっているのに、まだ作っていない物）から選んでわくに確かめる
2. 新しい会話で Claude に頼む（6章の最初のひとこと＋やりたいこと）
3. ブランチを作って、できたら PR（5章）

| 何をしていいか分からない | わくに聞く。わくは「何か質問ある？」と聞かれるのが好き |
