# モデリングの決まり（Claude と Argon 共通。これ1枚が正）

Oct 18 わくさんと決めた。モデリングの決まりはここだけに書く。AGENTS.md と `.claude/skills/modeling/` はここを指すだけ。
作る物ごとの中身は「モデル票」（`docs/modeling/<name>.md`、英語）に書く。わくさん用の日本語訳は `<name>_ja.md`。

## 1. 世界観チェック（形を決める前と、ラフを見せる前に、5問とも「はい」か）

1. **人の痕跡はないか**：人類が滅んだあとの熱帯の群島。コンクリート・金属の工業製品・文字・看板は出さない（ナメクジが拾って作り直した物はよい）
2. **ナメクジの手仕事か**：滑車、炭酸ガスの銃、油の灯、流木・つる・ヤシ縄・石・殻。粘液で作る魔法の道具（粘液工学）は出さない
3. **ナメクジの大きさで見て普通か**：世界は等身大。でかい木や岩は目印のときだけ。段差 0.45 m まで登れ、坂は 40〜50° まで這える
4. **雨に濡れて、くすんでいるか**：世界の物の彩度はナメクジより上げない。鮮やかなのはキャラと、珍しい物の1か所だけ
5. **シルエットで言えるか**：細部より形を大げさに。部品は少なく大きく。遠目の影だけで何か分かる

ナメクジの好み（形に効く）：湿った所・暗い所・狭い所が落ち着く。塩は敵（武器でもある）。

## 2. 寸法と書き出し（必ず守る）

- 1 単位 ＝ 1 m。ナメクジ：体長 1.1 m、目の高さ 0.47 m（人の約 1/3.6）、這う速さ 1.2 m/s
- 大きさは「ナメクジの何倍」と「人に置き換えると」の両方で言う
- 地面に置く物は底の真ん中が原点。上は Blender +Z、Unity +Y
- 滑らかな法線で書き出す。薄い部品（葉、布、板）も厚みのある閉じた形
- テクスチャは描かない（絵そのものが中身の物と、籠を運ぶ鳥の羽の模様だけ例外。Oct 19 わくさん）。部品ごとにマテリアルを分けて色で塗る。名前は `<物>_<部品>`。シェーダーは `Slug/Toon`、世界の物の値は `Assets/Art/Editor/WorldLook.cs`（質感リアル度 0.2）
- 三角形：手に持つ物 300〜1,500、採る場所 1,000〜4,000、名所・拠点の大物 5,000〜20,000（部品ごと）
- 当たり判定は Box・Capsule・凸の MeshCollider で別に作る
- 作り方はスクリプトに残す：`Blender/<種類>/<name>_gen.py` と同じ名前の `.blend`、FBX は `Assets/Art/Models/<種類>/<Name>/`（種類：Harvest・Base・Creatures・Landmarks・Props）。書き出しの設定は `Blender/Harvest/rocksalt_gen.py` の `export_fbx`。空の親に子を入れる入れ子は `bake_space_transform=False, axis_forward='Y', axis_up='Z'` ＋ Unity の Bake Axis Conversion ON（例 `Blender/Base/cenote_furniture_gen.py`）
- 使わない試作は消さずに `Assets/_Old/Art/`・`Blender/_Old/` へ

## 3. 進め方（食い違いを防ぐ）

わくさんの OK が出るまで次へ進まない。OK の印は ✅。

1. **読み返し票**（作る前。手は動かさない）：モデル票を読んで、下の形で返す。わくさん ✅ で次へ
   ```
   作る物：〜（1行）
   大きさ：ナメクジの〜倍／人なら〜
   置き場所と向き：〜（+Y が何の方向か）
   何をする所・物か：〜
   世界観チェック：1〜5 で気になる所（なければ「なし」）
   質問：2〜4個（読み違いそうな所。絵の向き、天井の有無、大きさ、場所、使い方。おすすめを1つ目に）
   ```
2. **灰色ラフ**：色なし。案を出すなら3案まで。必ず横に比べるナメクジ（体長 1.1 m・高さ 0.5 m のカプセル）。撮るのは決まった3枚だけ：
   - A ナメクジの目の高さ（0.47 m）から、いちばん大事な向き
   - B 横から、ナメクジと並べて（大きさが分かる）
   - C 真上か斜め上から全体（置き場所が分かる）
3. **色と細部**：✅ の案だけ。同じ3枚で撮る
4. **ゲームに入れる**：FBX → Unity のマテリアル → ナメクジの目の高さから撮る。ここで「完成」
5. **記録**：スクリプト冒頭のコメント（数字はここ）、`docs/README.md` の地図、相手に関係あれば `docs/worklog.md` に3行

直しは「どこを・どう・どれくらい」で受ける。「なんか違う」なら、違いそうな所を3つ挙げて極端に振った版を並べる。

## 4. トークンの節約（Oct 17〜18、Argon が1つの会話で2日やって約 4,000 万トークン使った反省）

AI は考えるたびに会話を最初から全部読み直す。会話が長いほど、1手ごとに高くなる。

- **1ステップ ＝ 1つの新しい会話**。上の 1〜5 の1つが終わったら会話を閉じる。続きはモデル票・スクリプト冒頭・worklog から始める（前の会話を覚えていなくて済むように、決まったことはファイルに書いてから閉じる）
- **最初に読むのは3つだけ**：AGENTS.md、このファイル、その物のモデル票（英語版）。`docs/spec.md`・`docs/discussions/`・参考の HTML は読まない（要ることはモデル票に書いてある。足りなければ読まずに質問する）。`_ja.md` は読まない
- **スクリプトは小さく分ける**：1ファイル 500 行まで（部屋ごと・部品ごとに分けて、本体から import）。直すときは **該当の関数だけ** 読んで部分直し。ファイルを丸ごと書き直さない
- **Blender で動かすときはコードを貼らない**：`exec(open(r"C:/.../xxx_gen.py", encoding="utf-8").read())` か import で実行。出力は「できた物の名前・三角形数・エラー」だけ数行 print する
- **絵は小さく少なく**：look は max_size 768 以下。1ステップで撮るのは上の3枚（案が3つなら 3×3 を1枚にまとめる）。撮り直しは直した所だけ。絵はファイルに保存し、何枚も見直さない
- **長い出力を出さない**：全オブジェクトの一覧や全頂点を print しない。数えた数だけ
- Claude も同じ：モデル票は英語で 150 行まで。決めた数字はモデル票に入れて、spec を読ませない

## 5. モデル票の書き方（Claude が書く）

`docs/modeling/<name>.md`（英語、150 行まで）と `<name>_ja.md`（日本語訳、わくさん用）。見出しは決まった順に：

1. **One line** — 何か1行。ナメクジ目線で何に見えればいいか
2. **Size** — ナメクジ比と m。置き場所と向き（+Y が何の方向か）
3. **Shape words** — 3つまで（ころん、ずんぐり、ごつごつ…。`.claude/skills/modeling/SKILL.md` の表）
4. **Parts** — 部品と、それぞれの寸法・マテリアル名・色（全部で 2〜4 色＋アクセント1）
5. **States** — 段階や状態があれば
6. **Do NOT** — 世界観チェックで外れやすい所を具体的に
7. **Deliverables** — スクリプト・.blend・FBX の場所、三角形の上限、当たり判定
8. **Open questions** — Claude が決めきれなかった所（読み返し票で答えを聞く）

参考の絵は1枚まで（小さく）。数字の根拠や話し合いの経緯は書かない（それは spec と discussions にある）。

## 6. ナメクジの動き（モーション）

Oct 18 わくさんと決めた。**Claude が Unity のコードで作る**（ボーンなし。這う波・伸び縮みはシェーダーとコード）。Argon はナメクジの体と動きに触らない（Blender で作った形は波に乗らない）。
前に食い違ったこと（Oct 3〜14）：腕の位置と浮き方が一人称と他人からで違った、振り返るとお尻が横すべり、縮んで伸びるが「ちょっと速い」、ピッケルの握る所と振り下ろす所、速さの値がコードの初期値と Tuning の2か所にあった。

1. **動き票**（作る前。Claude が書いて、わくさん ✅）
   ```
   動き：〜（1行。遊びで何が伝わればいいか。例：重い塩の塊を、体ごと叩き割る手応え）
   きっかけ：どのボタン／何が起きたら。続けて押したら・途中で離したら
   コマ：構え → 溜め → 動く → 当たる → 戻る。それぞれ「何秒」と「体・腕・道具がどこ」
         （向きは体から見て：右後ろ上、肩の高さ、など。握る所は右手・左手それぞれ）
   当たったら・ぶつかったら：止まる／跳ね返る／めり込まない
   一人称と他人から：それぞれ何が見えるか（腕は一人称では先だけ、など）
   体のついてき方：振り返る・止まる・坂で、尾や体がどう遅れてついてくるか
   音が合う瞬間：どのコマ
   参考：ゲームの動き1つと、どこが良いか
   やめて：〜
   ```
2. **止め絵（キーポーズ）**：動かす前に、コマごとの形を止めて撮る。上の段が一人称、下の段が横から（他人から 3 m）で、1枚に並べる。✅ が出るまで動かさない（形と向きのずれは、ここで見つける）
3. **動かす**：コマ撮り（`MoveFilmStrip`・`SwingFilmStrip`・`GunFilmStrip`。決まった時刻で撮って1枚に並べる）。一人称と他人からの両方を撮る
4. **手触りの数字はわくさんがスライダーで決める**：速さ・溜め・戻りの時間などは、最初から `Assets/Tuning/` の設定アセットにスライダー（Tooltip つき）で出す。Claude が入れるのは最初の値だけで、そのあとは触らない。コードの初期値とアセットの値が違うときは、アセットの値が正
5. **直しの言い方**：「何コマ目の・どこが・どう」（例：3コマ目の左手を柄の下へ）。速さはスライダーで

よくある失敗：止め絵だけで決めて、這う波・伸び縮み・振り返りで壊れる／一人称だけで決める／動きの途中で体や装備が埋まる（いちばん縮んだ瞬間と、いちばん伸びた瞬間を必ず撮る）。

## 7. 地形のコード（分けて、焼いて固める）

Oct 18 わくさんと決めた（無難の案）。地形はこれからも Unity のコードで作る。ただ、島のコードは 11 ファイル・約 3,900 行まで増えていて、読むたび、作り直すたびに重くなっていく。そこで次の2つを決まりにする。

- **1ファイル 500 行まで**：1つの造形か1つの場所につき1ファイル（partial class）。500 行を超えたら、関数のまとまりで分ける。共通の部品は `IslandTest800Tools.cs` などの道具のファイルへ。ファイルの冒頭には「何を作るか・数字・焼いたか」を書く
- **決まった所は焼いて固める**：わくさんの ✅ が出た造形は、出来上がりをアセットに保存して、それからは作り直さない。コードは消さないが、ふだんは読まない（読むのは冒頭のコメントだけ）。焼き方と、もう一度直すときの手順は `.claude/skills/modeling/shapes/README.md` の「焼いて固める」

## 8. わくさんの好み（直しから分かったこと）

形を決めるときに、まずここを見る。わくさんのフィードバックが来るたびに Claude が1行ずつ足す（どの物で・いつ）。

- **ポップはずんぐり寄り**：同じ物を3案（曲がり・まっすぐ高い・ずんぐり低い）並べたら、太く低い案が「めっちゃいい感じ」。背を低く、幹や胴を太く、葉や頭を大きめに（ヤシ、Oct 20）
- **知っている物は本物の大きさ**：ヤシの実のように、遊ぶ人が大きさを知っている物は、形をポップにしても本物の大きさ（ヤシの実は直径 約 28 cm）で付ける。ナメクジと比べて大きさが分かる手がかりになる。形に合わせて大きくすると、ナメクジくらいの大きさになって大きさの感じが崩れる（ヤシ、Oct 20）
- **幹や胴は思ったより明るい色に**：Slug/Toon の陰で、細く縦に長い物（幹など）はかなり暗く見える。ヤシの幹は #6E6253 では黒茶に見えて「もう少し明るく」→ #B0A28A にした。色はナメクジの目の高さ（下から見上げる）で Unity で確かめてから決める（ヤシ、Oct 20）
- **のっぺりは形と色の帯で直す（テクスチャは貼らない）**：ヤシの幹が「のっぺりして分かりづらい」→ 節を形で強く（半径の ±10%）して、溝だけ暗いマテリアルの帯にしたら、テクスチャなしで幹らしく読めた。シェーダーのまだら模様（`_MottleAmount`）は FBX の物では見えなかった（ヤシ、Oct 20）
